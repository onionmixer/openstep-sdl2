# SDL2 가 스스로 VRAM 에서 내보내게 하기 (C8 의 `(나)`)

> **되었다 (2026-08-29).**  응용은 함수 포인터 셋을 `SDL_SetWindowData` 로
> 걸어 두고 평범한 `SDL_GL_SwapWindow` 루프를 돈다.  800x600 에서
> **43.91 fps**, 되읽기 **0 회**.  공개 심볼은 **836 그대로**.
> stock Mesa 로 링크한 같은 라이브러리는 예전과 똑같이 동작한다.
> 실측표는 §10.

`(가)` 는 **응용이** 드라이버를 직접 불러 320x240 에서 162 배, 800x600 에서
54 fps 를 냈다.  `(나)` 는 그것을 **라이브러리 안으로** 옮겨, 평범한 SDL2
프로그램이 아무것도 모르고도 같은 속도를 받게 하는 것이다.

**요구사항이 하나 더 있다: Mesa 가 소프트웨어일 때도 되어야 한다.**

## 1. 소프트웨어 Mesa 는 사실 이미 빠르다 — 이것부터 바로잡는다

느린 것은 소프트웨어가 아니다.  stock Mesa 는 호출자의 배열에 **직접**
그리므로 되읽기가 아예 없다.  0.54 fps 는 **가속했을 때만** 나오는 값이고,
드라이버가 VRAM 표면을 대입한 뒤 매 브래킷마다 그것을 시스템 메모리로
끌어오기 때문이다.

그러므로 이 작업의 형태는 "소프트웨어도 지원한다"가 아니라

```
도장을 쓸 수 있으면 쓴다.
쓸 수 없으면 지금 그대로 한다.        <- 소프트웨어가 여기로 온다
```

이고, **두 번째 줄이 기본값**이어야 한다.  등록이 없으면 아무 일도 일어나지
않고, 그것이 stock Mesa 와 링크된 `libSDL2.a` 의 정상 동작이다.

## 2. 계층 — `libSDL2.a` 는 드라이버 심볼을 부를 수 없다

`libSDL2.a` 는 stock `libGL.a` 와도 링크되어야 하고 `OSMGAMesaBuffer*` 는
`libGL_mga.a` 에만 있다.  직접 참조하면 stock 빌드가 링크되지 않는다.

**답: 응용이 함수 포인터를 걸어 둔다.**

```c
/* 응용 쪽 (libGL_mga.a 를 링크한 프로그램만) */
static const SDL_OpenStepPresentHooks hooks = {
    OSMGA_PRESENT_ABI_1,
    OSMGAMesaBufferOrigin,
    OSMGAMesaBufferPresentMode,
    OSMGAMesaBufferPresentRect
};
SDL_SetWindowData(win, "OpenStep.GL.Present", (void *)&hooks);
```

`SDL_SetWindowData` 와 `SDL_GetWindowData` 는 **이미 이 라이브러리에 정의되어
있다** — 실기 `nm libSDL2.a` 에서 둘 다 `T` 로 확인했다.  그러므로

```
공개 심볼 836 개              그대로
stock Mesa 링크               그대로 (SDL2 안에 드라이버 이름이 없다)
등록하지 않은 프로그램         지금과 완전히 동일하게 동작
```

버전 워드 **하나로는 부족하다.**  구조체가 자라면 "버전이 같다"만 보고 뒤
필드를 읽다가 범위를 넘는다.  그러므로 앞의 두 워드는

```c
unsigned long abi;         /* OSMGA_PRESENT_ABI_1 */
unsigned long structSize;  /* sizeof(구조체) -- 필드마다 이것과 대조한다 */
```

이고, SDL 은 **쓰려는 필드가 structSize 안에 들어오는지, 그리고 NULL 이
아닌지**를 하나씩 확인한 뒤에만 부른다.

**포인터 수명도 계약이다**: 등록한 순간부터 같은 키에 NULL 을 넣고 그 뒤의
swap 이 더 이상 참조하지 않을 때까지 살아 있어야 한다.  **스택에 둔 구조체를
등록하는 것은 금지**다.  (문서에 적지 않으면 반드시 일어난다.)

## 3. 진짜 제약 — 방향은 라이브러리가 잡을 수 없다

`(가)` 는 절두체의 top/bottom 을 바꾸어 해결했다.  **라이브러리는 그렇게 할
수 없다.**  응용의 투영 행렬은 응용 것이다.

문제의 뿌리는 확인되었다:

```
yup=1 (가속이 요구하는 값)   GL 행 i -> 메모리 행 i
VRAM 스캔아웃                메모리 행 0 = 화면 맨 윗줄
따라서 VRAM 안의 그림은      거꾸로 서 있다
AppKit 비트맵 경로가 멀쩡한 이유: 그 비트맵이 아래→위라서 그냥 맞는다
도장이 뒤집히는 이유:        스캔아웃은 위→아래라서 안 맞는다
```

그리고 `yup=0` 은 쓸 수 없다.  하드웨어가 `VB->Win`(아래가 0)을 **메모리 행
y 로 그대로** 쓰기 때문에 소프트웨어(행 h-1-y)와 어긋나고, 그래서 상태 갱신이
`!yup` 을 **거절한다**.  (`REMAINING_WORK.md` §(1) 에 기록된 규약.)

```
A  행 단위로 거꾸로 도장     라이브러리만.  프레임당 h 번 ioctl.
                             비용 미지 -- 재야 안다.
B  present 에 상하반전 깃발   드라이버+커널.  AR5 는 이미 "부호 있는 소스 행
```

### A 를 쟀다 (2026-08-29)

데모에 모드를 하나 더 붙여 800x600 에서 실측했다.

```
                    도장      wall      fps    swap 대비
SDL swap              --   1847.41*    0.54      1.0x
행 단위 역순 도장   8.01 ms   22.87    43.72     81.0x

```

**커널 진입 한 번이 7.21 마이크로초다** (4.32 ms / 599 회).  이 프로젝트가
그 값을 가진 적이 없었으므로, 이것 자체가 얻은 것이다.

**A 는 쓸 만하다.**  B 의 80% 속도를 내면서 드라이버도, 커널도, 재부팅도
건드리지 않는다.  그러므로 `(나)` 는 **라이브러리 안에서 끝낼 수 있고**,
B 는 그 위의 선택지로 남는다 (4.32 ms 를 되찾는 값이 있을 때).

**순서: A 를 먼저 쟀다.**  A 가 쓸 만하면 `(나)` 는 라이브러리 안에서 끝나고
드라이버도 재부팅도 필요 없다.  A 가 못 쓸 만하면 그 숫자가 B 의 근거가 된다.
B 를 먼저 하는 것은 이 저장소가 M19 에서 한 번 밟은 순서다.

위 표가 그 측정이다.

## 4. 물러나야 하는 모든 경우

도장은 **창 합성이 아니라 화면에 도장을 찍는 것**이므로, 하나라도 어긋나면
AppKit 경로로 물러난다.  물러남은 예외가 아니라 **정상 동작의 절반**이다.

```
훅이 등록되지 않았다              stock Mesa, 또는 그냥 안 쓰는 응용
훅의 ABI 가 다르다
Origin() 이 거짓                  가속 표면이 아니다 (소프트웨어 폴백 중)
창이 숨겨졌거나 최소화됐다
창에 입력 초점이 없다             다른 응용이 위에 있다
창이 이번 프레임에 움직였다
목표 사각형이 화면 밖이다
창 크기가 표면 크기와 다르다
현재 문맥이 이 창의 것이 아니다     -- 5.5
다른 창이 이미 도장 주인이다        -- 5.5
present 가 거부했다                 -- 아래 표대로
```

**거부는 상태 변화이지 로그 한 줄이 아니다.**  판정마다 다르게 대응한다:

```
E_BUSY    엔진이 바쁘다              그 프레임만 건너뛴다
E_DST     목표가 화면을 벗어났다      다시 자르고 다음 프레임에 재시도
E_MODE    모드가 바뀌었다            이 창의 도장을 끈다
E_LATCH   가속이 영구 중단됐다        이 프로세스의 도장을 영구히 끈다
E_SRC     소스가 창을 벗어났다        표면/문맥이 어긋난 것이다 -- 이 바인딩의
                                     도장을 영구히 끈다
E_GEOM    크기가 0 이거나 담기지 않음  크기가 바뀔 때까지 끈다
E_MAGIC   구조체가 어긋났다           영구히 끈다 -- ABI 가 어긋난 것이다
ioctl 실패 자체                      영구히 끈다
```

그리고 **초점만으로는 가림을 판정하지 못한다.**  메뉴, 패널, 겹친 다른 창은
초점을 뺏지 않고도 이 사각형을 덮는다.  그러므로 이 설계는 "창 합성과
동등하다"고 주장하지 않는다 — **혼자 보이는 창일 때만 화면을 소유한다**는
제한이고, 그 밖은 AppKit 이 맞다.

## 5. expose — 여기가 가장 조용한 실패다

`(가)` 의 치명적 한계는 노출 때 낡은 AppKit 비트맵이 도장을 덮는 것이었다.

**이 계획의 첫 판은 "포트에 이미 `data->presenting` 이 있고 `drawRect:` 가
그것을 본다"고 적었다.  틀렸다.**  실제 코드는

```objc
- (void)drawRect:(NSRect)rect
{
    if (_bitmap != nil) { [_bitmap drawInRect:[self bounds]]; }   /* 무조건 */
    ...
    if (!data->presenting) { SDL_SendWindowEvent(..., EXPOSED, ...); }
}
```

이고, `presenting` 은 **expose 이벤트 발송만** 막는다.  비트맵 그리기는
막지 않는다.  즉 지금 상태로 도장을 켜면 노출 때마다 낡은 비트맵이 그림을
덮으며, 이것이 이 설계에서 **가장 조용하고 가장 즉각적인 실패**다.

그러므로 `(나)` 는 `drawRect:` 도 고쳐야 한다:

```
도장이 이 창을 소유하는 동안        비트맵을 그리지 않는다
                                    (뷰의 배경만 칠하거나 아무것도 안 한다)
노출을 받으면                        다음 프레임의 도장이 되찾는다
도장을 놓았으면                      예전대로 비트맵을 그린다
```

새 플래그가 필요하다.  `presenting` 을 재사용하면 안 된다 — 뜻이 다르다.

## 5.5 한 프로세스에 도장 주인은 하나뿐이다

드라이버의 상태는 **문맥별이 아니라 파일 정적**이다:

```c
static void *bufMapped;   /* 대입된 VRAM 표면 */
static void *bufApp;      /* 응용이 준 배열 */
static int   bufPresent;  /* 도장 모드 */
```

그러므로 `PresentMode(1)` 은 **프로세스 전체**를 바꾼다.  창이 둘이거나 한
창에 문맥이 여럿이면, 훅을 창마다 걸어도 어느 문맥의 표면인지 증명되지
않는다.  계약을 좁힌다:

```
도장은 한 번에 한 창, 한 문맥.
현재 문맥이 그 창의 것이 아니면 물러난다.
다른 창이 도장을 잡으려 하면 앞선 주인을 먼저 놓게 한다.
여러 스레드에서 동시에 GL 을 쓰는 경우는 지원하지 않는다.
```

## 5.6 도장을 놓을 때 배열은 저절로 맞춰진다 — 확인했다

**이 절의 첫 판은 틀렸다.**  "`PresentMode(0)` 은 깃발만 세우므로 물러남이
화면을 되찾지 못한다"고 적고 드라이버에 한 줄을 넣었다.  그 한 줄은
**필요 없었다.**

미러의 모든 경로가 이렇게 생겼다:

```c
if (bufPresent)  return;      /* 화면 전달 중 -- 배열은 낡은 것 */
if (... || !bufDirty) return;
bufDirty = 0;                 /* <- 위 반환보다 아래에 있다 */
```

`bufPresent` 검사가 `bufDirty = 0` **앞에** 있으므로, 도장을 찍는 동안
더티 표시는 **지워지지 않는다.**  마지막 렌더 시작에서 선 표시가 그대로
살아 있고, 도장을 놓으면 다음 flush 가 표면을 되읽어 배열에 넣는다.

**그 한 줄을 꺼서 다시 빌드해 보고 시험이 여전히 통과하는 것을 확인한 뒤**
되돌렸다.  일어나지 않는 일에 대한 수정을 싣지 않기 위해서다.

남는 것은 **시험**이다 (`openstep-sdl-gl-stampfallback.c`): 다섯 프레임을
찍고, 훅을 떼고, **아무것도 새로 그리지 않은 채** swap 해서, 비트맵이 마지막
그림을 담고 있는지 본다.  아무도 적어 두지 않은 불변식을 이것이 지킨다.

여전히 참인 것 하나: **swap 은 glFinish 앞에서 경로를 정해야 한다.**
도장을 놓는 것과 되읽기가 도는 것이 같은 flush 여야 하기 때문이다.

## 6. 수명주기

```
등록          SDL_SetWindowData, 응용이 문맥을 만든 뒤 언제든
해제          같은 키에 NULL -- 그러면 다음 swap 부터 AppKit
PresentMode   훅이 처음 쓰이기 직전에 1, 물러날 때 0
              (미러를 다시 켜야 AppKit 경로가 그림을 얻는다)
창 소멸       PresentMode(0) 을 반드시 부른다
크기 변경     표면이 하나 크기이므로 도장을 끄고 AppKit 으로
```

`PresentMode(0)` 를 빠뜨리면 **다음 AppKit swap 이 빈 화면을 그린다** —
미러가 서 있는 채로 배열을 읽게 되므로.  이것이 이 설계에서 가장 조용한
실패다.

## 8. 무엇을 주장하지 않는가

**"응용은 아무것도 모른다"는 달성되지 않는다.**  응용이 훅을 걸어야 하기
때문이다.  정확한 목표 문구는 이것이다:

> **등록한 뒤에는 응용의 draw/swap 루프가 바뀌지 않는다.**

이 절충은 정당하다.  정적 `libSDL2.a` 가 MGA 심볼을 참조할 수 없다는 것이
첫째 이유지만, 더 큰 이유는 도장이 **성능 최적화가 아니라 표시 소유권의
변경**이라는 것이다: 호출자 배열이 낡은 것이 되고, 창 서버의 합성을 우회한다.
그런 것을 묵시적으로 켜서는 안 된다.

## 9. 하지 않는 것

- `C`(가속이 yup=0 을 받아들이게 하기) 를 하지 않는다.  가속 경로 전체의
  좌표 규약을 바꾸는 일이다.
- `B` 를 지금 하지 않는다.  `A` 가 이미 43.72 fps 를 내고, `B` 는 커널
  변경과 재부팅과 **아직 확인되지 않은 레지스터 가설**을 요구한다:
  `SGN_BLIT_UP` 은 이 드라이버 안에서 **겹침 회피용 순서 제어**이고
  (`osmgaStormBlit` 은 up 일 때 소스와 목적지를 **둘 다** 마지막 행에서
  시작한다), 미러가 아니다.  미러를 만들려면 목적지는 아래로 걷게 두고
  소스만 거꾸로 걷게 해야 하는데 — `SGN` 을 down 으로 두고 `AR5 = -stride`,
  소스 시작을 마지막 행으로 — **그 두 제어가 독립인지 이 프로젝트는 확인한
  적이 없다.**  B 를 한다면 첫 작업은 ABI 변경이 아니라 2xN 색 줄무늬로
  그 조합을 실기에서 시험하는 것이고, 채택한다면 기존 블록에 필드를 붙이지
  말고 `PRESENT_V2` 로 따로 낸다 (ioctl 번호가 구조체 크기를 담으므로).
- 도장을 기본값으로 켜지 않는다.  등록하지 않은 응용은 오늘과 같아야 한다.
- 창 z-order 를 흉내내지 않는다.

```c
static const SDL_OpenStepGLPresent hooks = {
    SDL_OPENSTEP_GLPRESENT_ABI, sizeof(hooks),
    OSMGAMesaBufferOrigin, OSMGAMesaBufferPresentMode,
    OSMGAMesaBufferPresentRect
};
```

그 뒤로는 draw/swap 루프가 바뀌지 않는다 — 도장도, 사각형 계산도, 가드도
전부 SDL2 안에 있다.

### 10.1 규약이 실제 함수에 맞춰졌다

처음 규약은 `int (*surface_is_accelerated)(void)` 였는데 드라이버의 함수는
`unsigned long OSMGAMesaBufferOrigin(void)` 다.  컴파일러가
`incompatible pointer type` 으로 잡았고, **응용이 형변환으로 때우게 두지 않고
규약 쪽을 고쳤다** — 형변환을 요구하는 규약은 서명 불일치를 캐스트 뒤에
숨기는 규약이다.

### 10.2 아직 눈이 필요한 것

`drawRect:` 의 물러남(가림 뒤 복귀), 창을 끌 때의 잔상, 그리고 도장이
그림을 바로 세우는지 — 앞의 둘은 시험이 없고, 마지막은 운영자가 확인했다.
